# 立项宪章 · repo-watch

> 项目 slug:`repo-watch` · 创立日期:2026-10-09 · 基准货币:USD
> 本文件定义"这个项目要做成什么"和"什么算成功、什么算失败"。**成功线/止损线一旦写下就不轻易改动** —— 它是防止自我美化的唯一客观标尺。

## 1. 一句话目标
在 Windows 本机后台持续监控所有本地 git 仓库的远端更新,远端有新 commit 时弹系统 toast 通知,经确认后自动 `git pull`,每 30 分钟自动循环一次;开机自启,无需人工干预。

## 2. 为谁解决什么问题
- **目标人群**:使用 Windows、本地维护多个 git 仓库(个人开源 + 工作项目混合)的开发者
- **痛点**:
  1. 多仓库本地工作区状态分散,远端更新靠手动 `git pull` 才知道
  2. 重启电脑后监控工具需要手动再挂一遍,没有真正的"开机自启 + 后台常驻"
  3. 远端有更新但本地有脏工作区,直接 pull 会失败 —— 需要自动 stash + reapply
  4. 没有可观测的"上次扫描基线",重启后无法判断哪些仓库"真的在更新"
- **现在的替代方案**:手动 `git pull` + GitHub Web 看 star;或自己写定时脚本(但没人做完闭环)
- **为什么我会做得更好**:
  - 一键静默安装(bat → 依赖 → token → VBS → 后台 `pythonw` 四步),不污染 PATH
  - 30 分钟循环 + Windows 系统 toast(不占控制台、不占终端)
  - 脏工作区 `stash + pull + reapply` 自动闭环
  - `repo_watch_state.json` 记录基线,重启后无需重扫全仓库(省限流)
  - 已开源到 `lh123aa/repo-watch` 供他人参考

## 3. 变现假设(谁 + 痛 + 愿意付多少 + 凭什么判断)
- **谁**: 个人开发者(先自用), 再推向 Windows 上的远程办公 / 多仓维护型开发者; 长期可扩到 Mac/Linux 用户(经 L2 托管版)
- **愿意付多少**: 免费(开源) → $5–10/月(托管 SaaS L2) → $50–200/月(企业 L3, 薄市场); 一次性 $5–15 桌面包装版作为备选
- **判断依据**(四层变现模型, 详见 IN-0002):
  - L1 开源: GitHub star ≥ 50 或 clone ≥ 200 或 issue ≥ 10(30 天, 截止 2026-11-08)
  - L2 托管 SaaS 触发: L1 达标 且 ≥ 10 人 ask "有没有 mac/网页版"
  - L3 企业版触发: L2 月费 ≥ $100 且 Team ≥ 3 家 且 私有部署问询 ≥ 1
  - L4 案例资产: 当下就能做, 不等 S2, 3–5 篇短文 + 1 篇 3000 字案例 + 脱敏资产包
- **验证方式**:
  - L1: GitHub 公开仓库 + release + README, 统计 star / clone / issue
  - L2: 2 周 MVP sprint, 免费层 + Pro 订阅, Stripe 上线后看付费转化
  - L4: 案例阅读量 / 转发 / 资产包下载数

## 4. 成功线(达成即算变现成功,写客观可查的标准)
- **自用线**:从上线(2026-10-09)起连续 14 天,`pythonw` 常驻进程未因崩溃/手动 kill 中断过(重启后 VBS 自启算数),且本地至少 1 次成功 `git pull`(由 toast 确认,而非手工 pull)
- **开源线**(可延后):开源 30 天内 star ≥ 50 或 clone ≥ 200(取先到者)
- **收入线**(可选):若有付费包装版,连续 2 个月净收入 ≥ $50/月

## 5. 止损线(触发即停止投入,不允许"再试一个月")
- **技术线**:累计投入 ≥ 80 小时 且 14 天内出现 2 次以上"重启后 VBS 自启但 `pythonw` 崩溃无日志"的情况(I-024 不解决)
- **市场线**:开源 30 天 star < 10 且 clone < 50 → 停开源推广,只自用
- **健康线**:累计连续 2 周每天投入 > 4 小时 → 强制冷却 1 周

## 6. 关键约束
- **时间预算**:每周 ≤ 5 小时(自用不烧时间;开源推广另计)
- **资金预算**:累计不超过 $50(GitHub / 域名等基础设施)
- **不可触碰的底线**:不收集任何用户隐私数据;开源代码不含 token / 个人 git 凭据;PAT 必须可吊销

## 7. 明确不做(防止范围蔓延)
- **L1 开源版范围内**: 不做 Linux / macOS / GUI / SaaS / 写操作(pull 之外), 只读 + pull; 不自动 `git push`
- 不做"自动 PR / 合并 / 提 issue"
- **注意**: "不做跨平台 / 不做 SaaS" 是对 L1 开源版的约束; **L2 托管版 SaaS 若由 S2 数据触发(见 IN-0002 决策树), 则跨平台 + 网页 dashboard 是 L2 的核心卖点, 不在此约束内**
- 不做 L3 企业版, 直到 L2 月费 ≥ $100 且 Team ≥ 3 家且私有部署问询 ≥ 1(见 IN-0002)

## 8. 风险与依赖(最可能让项目死掉的 3 件事)
1. **重启后崩溃无日志**(I-024):`pythonw` 失败时 stderr 被丢弃,用户以为跑着其实没跑 → 需要启动自检 + 日志落地
2. **`win10toast` 在 Win11 24H2+ 兼容**(I-012):如果系统升级后 toast 不显示,核心体验直接废
3. **GitHub 匿名 60/h 限流**(I-013):多仓库场景下撞限,用户体感"不工作了"
