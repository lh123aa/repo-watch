# IN-0002 变现路径与具体方法

## 判断（不吹）
repo-watch 是"多仓库上游更新焦虑"的窄需求工具。本身不发财，是**验证你能不能把小工具做出真实需求**的赌注。变现结构 = 漏斗（免费层）→ 真收入（托管 SaaS）→ 薄市场（企业），并辅一条**当下就能走的副线**（案例/内容资产）。

## 四层变现模型
- **L1 免费开源（$0）**：漏斗 + 背书 + 需求验证裁判；S2 时钟 0/30 天，截止 2026-11-08
- **L2 托管 SaaS（$5–10/月）**：卖"免部署 + 跨平台"（不是再卖一次代码）；最小可行架构 FastAPI + APScheduler + Postgres + React + Stripe；免费层 3 仓库/30 分钟，Pro $7 无限仓库/5 分钟/多账号，Team $19 5 席位；启动条件 S2 达标 或 30 天安装≥100 且 ≥10 人 ask 跨平台
- **L3 企业版（$50–200/月）**：薄市场，默认不做；触发 L2 月费 ≥ $100 且 Team ≥ 3 且私有部署问询 ≥ 1
- **L4 案例 + 内容资产（当下就能做，不等 S2）**：3–5 篇 build-in-public 短文（知乎/即刻/X）+ S2 到期后 3000 字案例 + 脱敏资产包（$29–99）；不直接卖产品，卖"能把想法落地成开源项目"的可证明能力

## 决策树（S2 到期 2026-11-08 对照）
```
S2 数据
├─ star≥50 或 clone≥200 → 进 L2 MVP (2 周 sprint)
│  → Stripe 上线 → 月费 ≥ $100 且 ≥5 付费用户 → 继续 L2
│  → 有 ≥3 家 Team 付费 + 私有部署问询 ≥1 → 开 L3 企业
└─ star<10 且 clone<50 → 停 L1/L2 推广, 只保留 L4 案例资产
```

## 关键数字（进 metrics.csv）
- 当前状态（2026-10-09）：stars=0, private=False, S2 时钟 0/30 天
- 触发 L2：30 天安装 ≥ 100 且 ≥ 10 人 ask 跨平台
- 触发 L3：L2 月费 ≥ $100 且 Team ≥ 3 且 私有部署问询 ≥ 1
- 止损 L1+L2：S2 到期不达标 → 停推广，只保留 L4 案例资产

## 现实提醒
- L2 天花板：小众 SaaS，月入几百到几千刀，**不是**"财务自由"
- L4 当下就能启动：3–5 篇短文 + 1 篇 3000 字案例 + 1 个脱敏资产包
- 唯一稳的变现是 L4（可证明能力 + 案例资产），产品本身（L1/L2）是期权
